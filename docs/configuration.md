# Настройка

Все настройки — переменные окружения. Файл `.env` подключается флагом Node или подгружается сам из корня репозитория (см. `TILDA_ENV_AUTOLOAD` ниже):

```powershell
node --env-file=.env scripts/tilda.mjs --help
```

Шаблон — `.env.example` (только синтетические числа).

## Переменные `TILDA_*`

| Переменная | Обязательна | Назначение |
| --- | --- | --- |
| `TILDA_PROJECT_ID` | для онлайн-команд | Числовой ID проекта Tilda. Команда с другим `projectid` отклоняется. |
| `TILDA_PROTECTED_PAGES` | для онлайн-команд | Список ID страниц, защищённых от записи, через запятую. Переменная должна быть задана **явно**: пустое значение `TILDA_PROTECTED_PAGES=` разрешает запись во все страницы, отсутствие переменной — ошибка. |
| `TILDA_DEFAULT_PAGE` | нет | Числовой ID страницы, используемой при отсутствии `--page`. Для `page publish` не подставляется — нужен явный `--page`. |
| `TILDA_BASELINE_DIR` | нет | Путь для снимков, инвентаря, журнала и скриншотов. По умолчанию `site-baseline/` в корне репозитория. |
| `TILDA_BROWSER_PROFILE` | нет | Путь к отдельному профилю Chrome. По умолчанию `.browser-profile/`. |
| `TILDA_REFERENCE_DIR` | нет | Каталог слепков референс-сайтов (HTML, структура, картинки) для `reference fetch`. По умолчанию `site-reference/` в корне репозитория. |
| `TILDA_DONOR_PROJECT_ID` | для команд донора | Числовой ID проекта донора для `browser --donor`, `session --donor` и `donor …`. Должен отличаться от `TILDA_PROJECT_ID`. Агент находит его в слепке: атрибут `data-tilda-project-id` в разметке опубликованных страниц. |
| `TILDA_DONOR_BROWSER_PROFILE` | для команд донора, кроме `donor aliases`, `donor links`, `donor check` | Путь к профилю Chrome держателя донора, например `./.browser-profile-donor`. В профиле хранится сессия аккаунта донора. Трём командам из исключения хватает `TILDA_DONOR_PROJECT_ID`: держатель донора они не открывают, а читают сохранённый перечень его страниц. Должен отличаться от профиля тестового держателя. Относительный путь считается от текущей папки: запускайте из корня репозитория или задайте абсолютный путь. |

Все ID — положительные целые числа; иное значение даёт `ConfigError` и код выхода 2.

## Диагностика

| Переменная | Значения | Назначение |
| --- | --- | --- |
| `LOG_LEVEL` | `DEBUG`, `INFO` (по умолчанию), `WARN`, `ERROR` | Порог логов. Логи идут в stderr; stdout занят коротким итогом команды. `DEBUG` печатает тела запросов к Tilda без cookies. |
| `TILDA_ENV_AUTOLOAD` | `0` | Выключает автозагрузку `.env`. Без неё `scripts/tilda.mjs` сам подгружает `.env` из корня репозитория, если не заданы `TILDA_PROJECT_ID` и `TILDA_DONOR_PROJECT_ID`; заданные переменные не перезаписываются. Тесты запускают CLI с `0`. |

## Что не попадает в Git

Исключены `.gitignore`: `.env`, профили держателей `.browser-profile*/` (в том числе профиль донора с сессией его аккаунта), `site-baseline/`, `site-reference/`,
`scripts/plans/`, `node_modules/`, `*.log`. Адрес референса и ID страниц живут в этих каталогах
и в `.env`, в репозиторий они не попадают. Не помещайте в планы, снимки и журнал пароли, cookies или ключи API.

## Снятие защиты на один запуск

Флаг `promote --unprotect` снимает защиту живой страницы только на этот вызов; переменную
`TILDA_PROTECTED_PAGES` он не меняет. Это осознанное действие человека, а не настройка.
