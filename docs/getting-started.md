# Начало работы

## Требования

- Node.js 24 или новее;
- установленный Google Chrome;
- доступ к нужному проекту Tilda в Chrome (вход выполняет человек).

Единственная зависимость Node — `playwright-core` 1.63.0. Chrome не скачивается
автоматически: используется установленный в системе.

## Установка

Шаги выполняются по одному в PowerShell:

```powershell
git clone https://github.com/nimph977/tilda-toolkit.git
cd tilda-toolkit
npm ci
node scripts/tilda.mjs setup --site D:\Sites\example-site --project <ID проекта> --agent claude
node scripts/tilda.mjs --site D:\Sites\example-site doctor
```

Ожидаемый результат каждого шага:

| Шаг | Результат |
| --- | --- |
| `npm ci` | без ошибок |
| `setup` | итог `status: готово`, код выхода 0 |
| `doctor` | пункты `ok`, код выхода 0 |

Для Codex вместо `--agent claude` укажите `--agent codex`, для обоих агентов — `--agent all`.
Агенту можно поручить те же шаги готовым запросом: [Install with an AI agent](../README.md#install-with-an-ai-agent).

Если `node scripts/tilda.mjs` падает сразу, до отчёта (например, на старом Node.js), запустите
`node scripts/doctor.mjs`: он работает и на старом Node.js и называет нужную версию.

### Что сказал `doctor`

`doctor` только проверяет и печатает команды исправления, сам ничего не ставит. Код выхода 1 — есть
пункт `FAIL`; `WARN` код не меняет.

| Пункт | Что сказал | Что сделать |
| --- | --- | --- |
| `node` | `нужен Node.js 24 или новее, сейчас v…` | Установите Node.js по команде из строки `→` и откройте новый терминал. |
| `dependencies` | `зависимости не установлены` или `playwright-core … вместо …` | `npm ci` в папке репозитория. |
| `chrome` | `Google Chrome не найден` | Установите Google Chrome по команде из строки `→`; в скобках перечислены проверенные пути. |
| `git` | `git не найден — нужен только для git clone и обновления` | Установите git по команде из строки `→`, если нужно клонировать или обновлять репозиторий. |
| `repo-env` | `.env в корне репозитория не читается` | Перенесите файл в папку сайта и запускайте с `--site <папка>`. |
| `site` | `папка сайта не указана` | Добавьте `--site <папка сайта>` или выполните `setup`. |
| `site` | `папка сайта не найдена` или `в папке сайта нет .env` | Выполните `setup --site <папка> --project <ID проекта>`. |
| `site` | `TILDA_PROJECT_ID не задан или неверен` | Впишите ID проекта Tilda в `.env` сайта. |
| `site` | `список защиты TILDA_PROTECTED_PAGES пуст` | Для живого сайта перечислите в нём все страницы; для тестового проекта пустой список допустим. |
| `skill` | `скилл tilda-manager не установлен` или `копия скилла устарела` | `node scripts/tilda.mjs setup --agent claude` (или `codex`). |

## Первичная настройка

Данные сайта хранятся в отдельной **папке сайта** вне репозитория. `setup` создаёт её и кладёт
в неё `.env` из `.env.example` без чужих ID. Общую папку каталога шаблонов при необходимости
создайте сами и укажите в `TILDA_CATALOG_DIR`.

ID проекта — число `projectid` в адресе списка страниц проекта в кабинете Tilda:
`https://tilda.ru/projects/?projectid=<ID>`. Его записывает флаг `--project`. Если `.env` уже есть,
`setup` его не перезаписывает: пустой `TILDA_PROJECT_ID` он заполнит, а другой ID в файле — отказ с
кодом 1 (исправьте файл вручную или уберите `--project`).

Минимум для онлайн-команд — две переменные в `.env` сайта:

```
TILDA_PROJECT_ID=100001
TILDA_PROTECTED_PAGES=200001
```

`setup` оставляет `TILDA_PROTECTED_PAGES=` пустым: впишите ID страниц, которые нельзя менять.
Полный список — в [Настройке](configuration.md). `.env` из корня репозитория не читается, а папка сайта
не должна лежать внутри репозитория.

Каждой команде сайт задаётся флагом `--site <папка сайта>`. Для постоянной работы с одним сайтом в сессии
PowerShell один раз задайте `$env:TILDA_SITE_DIR = 'D:\Sites\example-site'` — тогда флаг можно не писать.

## Первый запуск

1. Откройте браузер-держатель и войдите в Tilda в появившемся окне:

   ```powershell
   node scripts/tilda.mjs --site D:\Sites\example-site session --page 200002
   ```

   Окно разворачивается только на время входа, затем сворачивается. Не закрывайте
   его между командами: сессия Tilda не переживает перезапуск Chrome. Посмотреть в окно
   можно командой `browser show`, свернуть обратно — `browser hide`.

   Не знаете `pageid` нужной страницы? Когда сессия уже есть, перечень страниц проекта
   покажет `node scripts/tilda.mjs --site D:\Sites\example-site page list`.

2. Снимите текущее состояние страницы:

   ```powershell
   node scripts/tilda.mjs --site D:\Sites\example-site snapshot --page 200002
   ```

   Ожидаемый результат: `status: снимки сняты`, файлы в `D:\Sites\example-site\site-baseline\`.

Дальше — [Рабочий цикл](workflow.md): план → `preview` → `apply` → `verify`.

## Если есть доступ к кабинету донора

Донор — аккаунт Tilda с сайтом-образцом. Если владелец добавил аккаунт донора сотрудником
в тестовый проект, сайт переносится через буфер аккаунта, без сборки по разметке.

1. Добавьте в `.env` папки сайта ID проекта донора и отдельный профиль его держателя
   (относительный путь считается от папки сайта):

   ```
   TILDA_DONOR_PROJECT_ID=100002
   TILDA_DONOR_BROWSER_PROFILE=./.browser-profile-donor
   ```

2. Поднимите держатель донора и войдите в аккаунт донора в появившемся окне:

   ```powershell
   node scripts/tilda.mjs --site D:\Sites\example-site browser start --donor
   node scripts/tilda.mjs --site D:\Sites\example-site session --donor
   ```

   Держатель донора работает рядом с тестовым, у каждого свой профиль. Проект донора
   команды только читают.

Дальше — [Рабочий цикл](workflow.md), раздел «Перенос через кабинет донора».

## Проверка на новом сайте

Внутренний API редактора Tilda не является стабильным публичным интерфейсом.
Перед работой на новом сайте выполните минимальную ручную приёмку **на отдельной
копии страницы**:

1. снять снимок (`snapshot`);
2. изменить один текстовый элемент планом (`apply`);
3. убедиться в `verify: 0 расхождений`;
4. осмотреть результат в редакторе;
5. выполнить откат по журналу (`rollback`).

До успешной приёмки не применяйте набор к рабочей странице.
Приёмка на втором независимом сайте пока не выполнена.

## Границы инструмента

Набор не предназначен для изменения полей форм, CRM, платежей, доменов и настроек
страницы. Эти действия выполняйте в интерфейсе Tilda вручную. При сборке по референсу
(`reference fetch → catalog capture → reference plan → apply`, см. [Рабочий цикл](workflow.md))
не переносятся Zero Block, HTML-блоки, формы и настройки сайта (шапка и подвал проекта);
их собирают вручную в интерфейсе Tilda.
