# Команды CLI

```
node scripts/tilda.mjs --site <папка сайта> <команда> [--page <pageid>] [--plan <файл>] [--out <путь>] [--json] [--dry-run]
```

Одна команда — один цикл в одном процессе. В stdout — короткий итог (≈20 строк) или JSON
при `--json`; подробности в файлах `<папка сайта>/site-baseline/`; логи — в stderr.

Из любой папки: `node <путь-к-репо>/scripts/tilda.mjs --site <папка сайта> …`. `.env` из корня репозитория не читается: настройки сайта берутся из `.env` папки сайта, а команды с данными без выбранного сайта отказывают с кодом `2` ([Настройка](configuration.md)).

## Команды

Онлайн-команды (помечены ●) требуют `TILDA_PROJECT_ID`, `TILDA_PROTECTED_PAGES` и живой
сессии в браузере-держателе. Остальные работают по локальным снимкам без сети.

| Команда | | Назначение |
| --- | --- | --- |
| `browser start\|stop\|status` | | Держатель браузера: Chrome открыт один раз и живёт между командами. По умолчанию команды поднимают его сами. С `--donor` — второй держатель для аккаунта донора со своим профилем (`TILDA_DONOR_BROWSER_PROFILE`); оба держателя работают одновременно. При старте держатель сбрасывает масштаб tilda.ru в своём профиле. |
| `browser show\|hide` | | Показать окно держателя на экране или свернуть обратно. Держатель стартует свёрнутым за пределами экрана, поэтому из панели задач окно до первого `show` не открывается. |
| `session` | ● | Открыть редактор, ответить «сессия жива» или дождаться входа человека (`--wait`). С `--donor` — вход аккаунта донора в его держателе: окно на экране только до входа, проект донора только читается. |
| `inventory` | ● | Инвентарь блоков страницы → `records/<pageid>/_inventory.json`. |
| `snapshot [recordid…]` | ● | Снимки блоков: `--plan` (затронутые планом), перечисленные `recordid` или все. |
| `apply` | ● | Инвентарь → снимки → подготовка → запись → перечитать → `verify` одним запуском. Требует `--plan`. |
| `verify` | ● | Перечитать затронутые планом блоки и сверить с payload, без записи. Требует `--plan`. |
| `rollback <запись>` | ● | Обратный план из записи журнала тем же циклом с той же сверкой. |
| `journal` | | Список записей журнала страницы. |
| `find <строка>` | | Адреса вхождений по локальным снимкам живых блоков страницы (по инвентарю). Снимки удалённых блоков пропускаются (`skippedStale`); без инвентаря — все снимки и предупреждение. |
| `replace <что> <на что>` | | План замены по всем адресам → `--out` (по умолчанию `<папка сайта>/plans/replace-<pageid>.json`). |
| `upload <файл>` | ● | Картинка с диска на CDN Tilda; в ответе готовый `set.image`. В плане можно писать `"image": {"file": "путь"}`. |
| `preview` | ● | Предпросмотр правки без записи и скриншот затронутых блоков. Требует `--plan`. |
| `shot` | ● | Скриншоты вида страницы (`--width`), при `--links` — заодно проверка ссылок. |
| `links` | ● | Битые ссылки и картинки вида страницы. |
| `map` | ● | Карта блоков: скриншот с подписанными номерами и легенда `<ISO>-map.json`; файл открывается человеку (`--no-open` отключает). |
| `page duplicate\|create\|publish\|delete` | ● | Дубль страницы; пустая страница из шаблона; публикация **только** с явными `--page` и `--confirm`; для `delete` — инструкция человеку. |
| `page list` | ● | Перечень страниц проекта из кабинета без ключей API: идентификаторы, заголовки, адрес, статус публикации, папка, роль (главная, шапка, подвал, 404) и отметка защищённых. Полный список — в файл, в stdout — итог с первыми пятью страницами. `--page` и `TILDA_DEFAULT_PAGE` не нужны. Код `1` — ответ кабинета не распознан. |
| `promote` | ● | Накат проверенного плана с копии (`--from`) на живую страницу (`--to`) через бэкап-дубль. |
| `stage` | | Накопительный план реплик: `stage '<json-операция>'`, `stage --plan <файл>`, `stage diff\|apply\|drop\|list`. Локальный diff без сети. |
| `page role` | ● | Страница-шапка и страница-подвал проекта (`--header <id\|none> --footer <id\|none>`) или главная страница проекта (`--index <pageid>`, отдельным запуском); только с `--confirm`, перед записью — запись для отката, после — перечитывание. |
| `page title` | ● | Заголовок страницы в кабинете (`--page <id> --title <текст>`, до 120 символов) через окно настроек страницы; защищённая страница — отказ до запроса. |
| `reference fetch\|structure` | ● (fetch) | Слепок референс-сайта через держатель (`--url --slug`, `--follow --sitemap --max --images`), пересборка структуры без сети. Не требуют `TILDA_PROJECT_ID` и `TILDA_PROTECTED_PAGES` — нужен только держатель, вход в Tilda не нужен. |
| `reference pages` | ● (`--create`) | Карта сайта: метки `P00…`, `HDR`, `FTR` ↔ страницы слепка и новые `pageid` (`site.json`); `--create` создаёт недостающие страницы проекта. |
| `reference plan` | ● | План сборки `newRecord` по структуре, каталогу и картам влияния (`--source <имя\|метка> --page`, `--zone`, `--no-styles`, `--substitute`); с `--update` — дописывание уже собранной страницы метки операциями `field`/`listSet`. |
| `reference shot` | ● | Снимок страницы референса той же механикой, что `shot` (`--slug --source --width`). |
| `reference audit` | ● | Ссылки собранной страницы: нет домена референса, каждая `/page<id>.html` есть в `page list`, относительный адрес (`/company`) — адрес страницы из `page list` (иначе нарушение «относительный адрес без страницы в проекте»: на публикации 404). Ссылка `/page<id>.html` на страницу донора из карты сайта — отдельный вид «ссылка на страницу донора по ID — donor links». |
| `reference project` | ● | Шрифты, веса и цвета проекта референса → настройки тестового проекта; запись только с `--apply --confirm`, перед ней — запись для отката. |
| `reference compare` | ● | Поблочная сверка разметки собранной страницы с референсом (`--slug --source`, `--published --url`) → `compare/<метка>.json` и доклад `reports/<метка>.auto.md`. |
| `catalog capture\|list` | ● (capture) | Эталонные поля шаблонов: снять на черновой странице (`--page --slug\|--tplid`; блок каждого шаблона создаётся, читается и удаляется), показать снятое без сети (колонка `calibrated`). |
| `catalog calibrate` | ● | Карта «значение настройки → разметка» по предпросмотру (`--page <черновая> --slug\|--tplid`, `--force`, темп `--delay --batch --pause`); временный блок создаётся и удаляется. |
| `donor pages` | ● | Перечень страниц проекта донора под его входом → `pages/<projectid донора>.json`. Нужны `TILDA_DONOR_PROJECT_ID` и `TILDA_DONOR_BROWSER_PROFILE`. |
| `donor map` | | Метки карты сайта ↔ страницы донора по адресам и ролям (`--slug`): поле `donorPageid` в `site.json` и причины для несопоставленных меток. Без сети; сначала `donor pages`. |
| `donor copy` | ● | Перенос блоков страницы донора на страницу тестового проекта через буфер аккаунта донора (`--slug --source <метка>` или `--from <pageid донора> --to <pageid>`, `--replace`, `--dry-run`). Действие под входом донора — только по явному «делай» владельца. Приёмник получает заголовок по метке, если он ещё «Blank page», и адрес своей страницы донора, если адреса у него нет. |
| `donor style` | ● | Оформление и свой шрифт донора из его настроек → `<slug>/donor-style.json`; с `--apply --confirm` — в тестовый проект: шрифт ссылками на файлы донора, цвета и веса через форму настроек. Запись для отката — цвета, веса и размер текста; загруженный шрифт и его назначение при загрузке не откатываются (шрифт остаётся в проекте — это безвредно). |
| `donor verify` | ● | Сверка перенесённой страницы (`--slug --source`, `--width`): состав видимых блоков против слепка, сверка разметки, кадры сборки и референса, перечень HTML-блоков (пустые заглушки, внешние хосты), доклад `reports/<метка>.transfer.md`. Повторный запуск переносит заполненный «Вердикт агента» с пометкой о дате прежнего доклада. |
| `donor aliases` | ● | Адреса страниц копии как у их страниц донора (`--slug`, `--dry-run`) по файлам `donor pages` и `page list`. Шапка, подвал и главная пропускаются, адрес другой страницы не отбирается, у каждого пропуска причина. Вход донора не нужен. |
| `donor links` | ● | Ссылки донора в живых блоках метки → пути на страницы копии (`--slug --source`, `--dry-run`): адреса на домене донора и ссылки `/page<ID донора>.html` (относительные, на домене донора и на его поддомене `*.tilda.ws`) — по парам карты сайта. Меняется только адрес ссылки. Путь без страницы в копии и поля форм (`formmsgurl`) остаются с причиной. Снимок до записи, `verify` после, план — `<папка сайта>/plans/donor-links-<slug>-<метка>.json`. |
| `donor check` | ● | Проверки после переноса по меткам слепка (`--slug`, `--source P01,P02`; по умолчанию — все перенесённые метки, дубли страниц донора пропускаются с причиной): ссылки вида страницы (домен донора, относительные адреса, страницы донора по ID), HTML-блоки, `formmsgurl` на домене донора, полнота карты, главная страница проекта. Только чтение, пауза 3 с между метками. Итог — `reports/checks.json` и раздел между маркерами в `reports/transfer-summary.md` с ручными пунктами. Код 1 — нарушения ссылок, сбои меток, неполная карта или не та главная; при «главная не та» — готовая команда `page role --index <pageid> --confirm` в разделе сводки и в `next`. |

## Флаги

| Флаг | Команды | Назначение |
| --- | --- | --- |
| `--page <pageid>` | большинство | Страница; иначе `TILDA_DEFAULT_PAGE`. Для `apply`/`rollback` должен совпадать со страницей плана/записи. |
| `--plan <файл>` | `apply`, `verify`, `preview`, `snapshot`, `stage`, `promote` | План операций JSON. |
| `--out <путь>` | `replace`, `page list` и др. | Куда положить результат. |
| `--site <папка>` | все, кроме справки | Папка сайта вне репозитория: `.env`, `site-baseline`, `site-reference`, `.browser-profile`, `plans` (или переменная `TILDA_SITE_DIR`). Относительный путь считается от текущей папки. Без сайта команды с данными отказывают с кодом `2`. |
| `--json` | все | Итог в stdout как JSON; у `page list` — вместе с полным массивом `list`. |
| `--dry-run` | `apply`, `rollback`, `donor copy`, `donor aliases`, `donor links` | Ничего не писать в Tilda; у `donor copy` — показать план переноса: блоки донора, приёмник, будет ли очистка. |
| `--wait <сек>` | `session` | Сколько ждать входа человека (по умолчанию 600). |
| `--donor` | `browser`, `session` | Держатель и вход аккаунта донора (`TILDA_DONOR_PROJECT_ID`, `TILDA_DONOR_BROWSER_PROFILE`). Командам `donor …` флаг не нужен: роль задаёт сама команда. |
| `--replace` | `donor copy` | Снять блоки приёмника в `records/`, удалить их и перенести заново. Без флага непустой приёмник — отказ `TARGET_NOT_EMPTY`. |
| `--title <текст>` | `page title` | Новый заголовок страницы. |
| `--emit-calls` | `apply` | Дополнительно писать отладочные `*.call.js`. |
| `--width <список>` | `shot`, `map`, `reference shot`, `donor verify` | Ширины через запятую (по умолчанию `1440,320`). |
| `--links` | `shot` | Заодно проверить ссылки и картинки. |
| `--no-open` | `map` | Не открывать карту в просмотрщике. |
| `--confirm` | `page publish`, `page role`, `reference project`, `donor style` | Явное подтверждение публикации, смены шапки, подвала и главной, записи оформления проекта; без него — отказ. |
| `--from` / `--to` | `promote`, `donor copy` | `promote`: рабочая копия и живая страница; обе обязательны, числа, не равны. `donor copy`: страница донора и страница-приёмник тестового проекта — вместо `--source`. |
| `--unprotect` | `promote` | Снять защиту живой страницы на этот вызов. |
| `--batch` / `--delay` / `--pause` | `promote` | Темп полных снимков: чтений в пачке (10), мс между чтениями (2500), секунд между пачками (60). Для `reference fetch` и `catalog capture` `--delay` — мс между страницами / эталонами (2500). |
| `--url <адрес>` | `reference fetch` | Страница референса, с которой начинается обход. |
| `--slug <имя>` | `reference`, `catalog capture`, `catalog calibrate`, `donor map\|copy\|style\|verify\|aliases\|links\|check` | Имя слепка в `TILDA_REFERENCE_DIR` (латиница, цифры, дефис; домен в путях не участвует). |
| `--source <имя\|метка>` | `reference plan`, `shot`, `audit`, `compare`, `donor copy`, `donor verify`, `donor links`, `donor check` | Имя страницы из слепка (`index` для главной) или метка карты сайта (`P07`, `HDR`, `FTR` — страница, зона и замены из `site.json`). У `donor copy` — только метка с `donorPageid`; у `donor check` — метки через запятую. |
| `--zone all\|content\|header\|footer` | `reference plan` | По имени страницы — собрать только зону (по метке зона берётся из `site.json`). |
| `--no-styles` | `reference plan` | Не переносить оформление блоков: отступы, цвет фона, типографику. По умолчанию оформление переносится. |
| `--update` | `reference plan` | Дописать уже собранную страницу метки операциями `field`/`listSet` (без пересоздания блоков) → `<папка сайта>/plans/reference-<slug>-<метка>-update.json`. |
| `--apply` | `reference project`, `donor style` | Записать оформление в настройки тестового проекта (нужен `--confirm`). |
| `--published` | `reference compare` | Сверять опубликованную страницу по `--url` (адрес даёт владелец). |
| `--sitemap` | `reference fetch` | Добавить в очередь страницы из `sitemap.xml` того же сайта. |
| `--create` | `reference pages` | Создать в проекте недостающие страницы карты (пустые, по одной, пауза `--delay` мс, 3000). |
| `--header` / `--footer` | `page role` | Страница-шапка и страница-подвал (`<id>` или `none`), только с `--confirm`. |
| `--index` | `page role` | Главная страница проекта (`<pageid>`; снять нельзя, вместе с `--header`/`--footer` — отказ); защищённая страница — отказ `PROTECTED_PAGE`; откат — `page role --index <прежняя> --confirm`. |
| `--substitute <a>=<b>` | `reference plan` | Собирать блоки шаблона `a` шаблоном `b` — обход для меню, которое Tilda не даёт добавить. Флаг можно повторять или перечислять пары через запятую; при повторе одного `a` побеждает последняя пара. |
| `--follow` | `reference fetch` | Идти по внутренним ссылкам того же сайта. |
| `--max <n>` | `reference fetch` | Страниц за запуск (по умолчанию 20); повторный запуск продолжает с места остановки. |
| `--images` | `reference fetch` | Скачать картинки блоков в `images/`. |
| `--settle <мс>` | `reference fetch` | Ожидание после загрузки страницы (1500). |
| `--tplid <список>` | `catalog capture`, `catalog calibrate` | Шаблоны через запятую вместо `--slug` (например `796,702`). |
| `--force` | `catalog capture`, `catalog calibrate` | Переснять уже снятые шаблоны / перекалибровать откалиброванные. |
| `--batch` / `--delay` / `--pause` | `catalog calibrate` | Темп предпросмотров: в пачке (60), мс между ними (300), секунд между пачками (60). Полная калибровка 40 шаблонов — около 5,5 часа. |
| `-h`, `--help` | | Справка. |

## Коды выхода

| Код | Значение |
| --- | --- |
| `0` | Успех. |
| `1` | Расхождение при `verify` или отказ операции (защищённая страница, публикация без `--confirm`, `SHOT_SCALED` — масштаб окна искажает кадр, `TARGET_NOT_EMPTY`, `DONOR_CHANGED`, `WRITE_NOT_ALLOWED`). |
| `2` | Ошибка аргументов или конфигурации (`UsageError`, `ConfigError`). |
| `3` | Сессия Tilda потеряна (`SESSION_LOST`) — войдите заново через `session`. |

## Файлы результата

| Путь (внутри `TILDA_BASELINE_DIR`, по умолчанию `<папка сайта>/site-baseline`) | Содержимое |
| --- | --- |
| `records/<pageid>/_inventory.json` | инвентарь блоков |
| `records/<pageid>/<recordid>.json`, `zero/<pageid>/<recordid>.json` | снимки стандартных и Zero-блоков |
| `snapshots-index.json` | журнал снимков: что, когда, откуда |
| `journal/<pageid>/*.json` | записи журнала для `rollback` |
| `project-settings/<projectid>/<ISO>.json` | запись для отката `page role`: роли до, запрошенные, после, `otherChanged`; команда отката — в итоге `page role` |
| `project-settings/<projectid>/<ISO>-style.json` | запись для отката `reference project --apply` и `donor style --apply`: значения до, желаемые, после, `otherChanged` |
| `shots/<pageid>/` | скриншоты `shot` |
| `pages/<projectid>.json` | перечень страниц проекта (`page list`, `donor pages` — для проекта донора): `pages[]` и счётчики пропусков `skipped` |
| `transfer/<pageid>/<ISO>.json` | запись переноса `donor copy`: блоки донора, приёмник, снятые при `--replace` блоки, сверка `orderMatches` и `donorUnchanged` |
| `TILDA_CATALOG_DIR/<tplid>.json` (общая для всех сайтов) | эталонные поля шаблона (`catalog capture`): вкладки, значения по умолчанию, ключи карточек |
| `TILDA_CATALOG_DIR/<tplid>.settings.json` | карта влияния настроек шаблона (`catalog calibrate`): правило на поле — вариант, слот значения или текст |
| `<папка сайта>/plans/` | планы `replace`, `stage` и `reference plan` (`reference-<slug>-<source>-<page>.json`) |
| `TILDA_REFERENCE_DIR/<slug>/` (по умолчанию `<папка сайта>/site-reference/`) | слепок референса: `reference.json` (манифест; пути файлов — от папки слепка), `pages/*.html`, `structure/*.json`, `images/`, `site.json` (карта сайта), `project.css` и `project-style.json` (оформление проекта), `compare/` и `reports/` (сверка). В структуре у каждого поля есть `text` (видимый текст) и `html` (он же с `<br>` на переносах), у блока — `styles` (отступы, фон, типографика), `soclinks` и `linkhook` |
| `TILDA_REFERENCE_DIR/<slug>/donor-style.json` | оформление и шрифты донора (`donor style`), ключи, которые форма не пишет (`skipped`) |
| `TILDA_REFERENCE_DIR/<slug>/transfer/<метка>.json`, `reports/<метка>.transfer.md` | данные и доклад сверки `donor verify` с разделом «Вердикт агента» |
| `TILDA_REFERENCE_DIR/<slug>/reports/transfer-summary.md` | сводка переноса сайта: таблица меток, итоговые числа, ложные отличия предпросмотра; составляет агент по докладам. Раздел между `<!-- donor-check:start -->` и `<!-- donor-check:end -->` пишет `donor check` |
| `TILDA_REFERENCE_DIR/<slug>/reports/checks.json` | итог `donor check`: метки, нарушения, HTML-блоки, формы, полнота карты, главная, ручные пункты |
