# Начало работы

tilda-toolkit — неофициальный инструмент: он позволяет ИИ-агенту (Claude Code или Codex) читать и аккуратно
править страницы вашего сайта на Tilda через Google Chrome. Эта страница ведёт от пустой папки до работающей
установки. Установка удалась, если команда проверки `doctor` напечатала `итог: ok`.

## Install with an AI agent

Откройте Claude Code или Codex в пустой папке и вставьте запрос:

<!-- agent-prompt:start -->
```text
Установи tilda-toolkit из https://github.com/nimph977/tilda-toolkit.
1. Склонируй репозиторий и выполни в нём npm ci.
2. Выполни node scripts/tilda.mjs setup --site <папка сайта вне репозитория> --project <ID проекта Tilda> --agent claude
   (для Codex — --agent codex). Папку сайта и ID спроси у меня.
3. Выполни node scripts/tilda.mjs --site <папка сайта> doctor и покажи мне итог.
   Успех — «итог: ok» и код выхода 0; одно предупреждение WARN о пустом списке защиты для тестового проекта — норма.
4. Если doctor пишет FAIL — покажи мне его команду исправления и спроси, прежде чем
   что-то устанавливать. Системные программы без моего согласия не ставь.
```
<!-- agent-prompt:end -->

Агент спросит у вас две вещи:

- **Папку сайта**: новую папку на вашем компьютере вне склонированного репозитория, где инструмент хранит
  настройки одного сайта Tilda (файл `.env`). Вы только выбираете путь, например `~/tilda-sites/my-site`;
  папку создаст `setup`.
- **ID проекта**: число `projectid` в адресе списка страниц проекта в кабинете Tilda:
  `https://tilda.ru/projects/?projectid=<ID>`.

В конце агент покажет, что напечатал `doctor`. Это успех, если вы видите `итог: ok`, код выхода 0 и ровно одно
предупреждение `WARN` о том, что список защиты пуст. В этом списке лежат ID страниц, которые инструмент
не должен менять; для тестового проекта (проекта Tilda, который нужен только чтобы попробовать инструмент)
его нормально оставить пустым. Если вы видите `FAIL`, агент покажет команду исправления из `doctor` и
дождётся вашего согласия; сам он программы не устанавливает.

`setup` также ставит **скилл** `tilda-manager` — набор инструкций, который учит агента безопасно работать
с Tilda. Он кладётся в папку агента внутри репозитория (`.claude/skills/tilda-manager` или
`.agents/skills/tilda-manager`). После установки перезапустите сессию агента в папке репозитория, чтобы агент
подхватил скилл. Повторный `setup` обновляет копию, а `doctor` сообщает, если она устарела.

Другие агенты: пусть прочитают [AGENTS.md](../../AGENTS.md) и [skills/tilda-manager/SKILL.md](../../skills/tilda-manager/SKILL.md).

## Требования

Подготовьте до первой команды:

- аккаунт Tilda с проектом и ID этого проекта (число `projectid` в адресе
  `https://tilda.ru/projects/?projectid=<ID>`); вход в Tilda в Chrome человек выполняет позже, при первом запуске;
- Node.js 24 или новее;
- установленный Google Chrome;
- git (только чтобы склонировать репозиторий).

Если чего-то не хватает, `doctor` назовёт это и напечатает команду установки; как ставить программы,
эта страница не учит.

Единственная зависимость Node — `playwright-core` 1.63.0. Chrome не скачивается
автоматически: используется установленный в системе.

## Установка

Второй способ, для работы в терминале: шаги выполняются по одному. Команды написаны для bash
(macOS, Linux; в Windows — Git Bash, терминал, который ставится вместе с git для Windows, либо пусть агент
переведёт их в PowerShell). Замените `<ID проекта>` на ID вашего проекта. Папку сайта `~/tilda-sites/example-site`
(место для настроек одного сайта, см. выше) создаст `setup`; можно выбрать другой путь вне репозитория.

<!-- newcomer-path:start -->
```bash
git clone https://github.com/nimph977/tilda-toolkit.git
cd tilda-toolkit
npm ci
node scripts/tilda.mjs setup --site ~/tilda-sites/example-site --project <ID проекта> --agent claude
node scripts/tilda.mjs --site ~/tilda-sites/example-site doctor
```
<!-- newcomer-path:end -->

Ожидаемый результат каждого шага:

| Шаг | Результат |
| --- | --- |
| `npm ci` | без ошибок |
| `setup` | несколько строк `INFO [...]` (журнал; он пишется в stderr — поток ошибок, и это не ошибки), затем итог `status: готово`; код выхода 0 |
| `doctor` | `итог: ok`, код выхода 0 и ровно одно `WARN site … список защиты TILDA_PROTECTED_PAGES пуст` — для тестового проекта это норма |

Строки, начинающиеся с `INFO [...]`, — журнал инструмента. Он идёт в stderr, поток ошибок, поэтому может
появляться на экране рядом с результатами; это не значит, что что-то пошло не так. Ошибку означают только
строки `FAIL` и ненулевой код выхода.

Сразу после `npm ci` `doctor` без `--site` проверяет только программы (`skip site`) и тоже даёт
`итог: ok`. Это промежуточная проверка для тех, у кого ещё нет аккаунта Tilda, а не конец пути.

Для Codex вместо `--agent claude` укажите `--agent codex`, для обоих агентов — `--agent all`.

Язык сообщений выбирается флагом `--lang en|ru` или переменной `TILDA_LANG` (подробнее — [Язык сообщений](configuration.md#язык-сообщений)); например, `setup --lang ru` ещё и запишет язык в `.env` сайта.

Если `node scripts/tilda.mjs` падает сразу, до отчёта (например, на старом Node.js), запустите
`node scripts/doctor.mjs`: он работает и на старом Node.js и называет нужную версию.

### Что сказал `doctor`

`doctor` только проверяет и печатает команды исправления, сам ничего не ставит. Код выхода 1 — есть
пункт `FAIL`; `WARN` код не меняет.

В первой колонке — шаблоны сообщений в том виде, как их печатает `doctor`; вместо подставляемых значений
стоят имена в фигурных скобках (`{min}`, `{path}`).

<!-- doctor-messages:start -->
| Что сказал | Пункт | Что сделать |
| --- | --- | --- |
| `нужен Node.js {min} или новее, сейчас v{version}` | `node` | Установите Node.js по команде из строки `→` и откройте новый терминал. |
| `нужен Node.js {min}+` | все пункты после `node` | Они пропущены (`skip`), пока Node.js старый: обновите его, и остальные проверки выполнятся. |
| `зависимости не установлены` | `dependencies` | `npm ci` в папке репозитория. |
| `playwright-core {actual} вместо {expected}` | `dependencies` | `npm ci` в папке репозитория. |
| `Google Chrome не найден` | `chrome` | Установите Google Chrome по команде из строки `→`; в скобках после сообщения перечислены проверенные пути. |
| `система {platform} не поддерживается каналом chrome` | `chrome` | Запустите инструмент в Windows, macOS или Linux: для других систем путь к Chrome неизвестен. |
| `git не найден — нужен только для git clone и обновления` | `git` | `WARN`. Установите git по команде из строки `→`, если нужно клонировать или обновлять репозиторий. |
| `.env в корне репозитория не читается` | `repo-env` | `WARN`. Перенесите файл в папку сайта и запускайте с `--site <папка>`. |
| `папка сайта не указана` | `site` | `skip`. Добавьте `--site <папка сайта>` или выполните `setup`. |
| `TILDA_PROJECT_ID не задан или неверен` | `site` | Впишите ID проекта Tilda в `.env` сайта. |
| `TILDA_PROTECTED_PAGES не задан (пустое значение допустимо)` | `site` | Впишите в `.env` сайта строку `TILDA_PROTECTED_PAGES=`. |
| `TILDA_PROTECTED_PAGES содержит неверное значение` | `site` | Впишите в `TILDA_PROTECTED_PAGES` ID страниц через запятую. |
| `список защиты TILDA_PROTECTED_PAGES пуст` | `site` | `WARN`. Для живого сайта перечислите в нём все страницы; для тестового проекта пустой список допустим. |
| `скилл tilda-manager не установлен` | `skill` | `WARN`. `node scripts/tilda.mjs setup --agent claude` (или `codex`). |
| `копия скилла устарела: {path}` | `skill` | `WARN`. `node scripts/tilda.mjs setup --agent claude` (или `codex`). |
| `{path} создан не setup` | `skill` | `WARN`. Удалите ярлык вручную или перенесите папку (как сказано в строке `→`) и повторите `setup`. |
| `проверка не выполнена: {reason}` | любой пункт | Пункт не смог отработать; причина — в `{reason}`. Исправьте её и запустите `doctor` снова. |
<!-- doctor-messages:end -->

Если папку сайта не удалось выбрать или прочитать `.env`, пункт `site` печатает `FAIL` с текстом этой ошибки:
`папка сайта не найдена: …`, `в папке сайта нет .env: …`, `--site и TILDA_SITE_DIR указывают на разные папки: …`,
ошибку о папке внутри репозитория или о переменных, заданных и в окружении, и в `.env`. Под ним — команда
исправления: `setup --site <папка> --project <ID проекта>` либо совет выбрать одну папку, папку вне репозитория
или исправить файл `.env`.

## Первичная настройка

Данные сайта хранятся в отдельной **папке сайта** вне репозитория. `setup` создаёт её и кладёт
в неё `.env` из `.env.example` без чужих ID. Общую папку каталога шаблонов при необходимости
создайте сами и укажите в `TILDA_CATALOG_DIR`.

ID проекта — число `projectid` в адресе списка страниц проекта в кабинете Tilda:
`https://tilda.ru/projects/?projectid=<ID>`. Его записывает флаг `--project`. Если `.env` уже есть,
`setup` его не перезаписывает: пустой `TILDA_PROJECT_ID` он заполнит, а другой ID в файле — отказ с
кодом 1 (исправьте файл вручную или уберите `--project`).

Минимум для онлайн-команд — две переменные в `.env` сайта:

```
TILDA_PROJECT_ID=100001
TILDA_PROTECTED_PAGES=200001
```

`setup` оставляет `TILDA_PROTECTED_PAGES=` пустым: впишите ID страниц, которые нельзя менять.
Полный список — в [Настройке](configuration.md). `.env` из корня репозитория не читается, а папка сайта
не должна лежать внутри репозитория.

Каждой команде сайт задаётся флагом `--site <папка сайта>`. Для постоянной работы с одним сайтом в сессии
PowerShell один раз задайте `$env:TILDA_SITE_DIR = 'D:\Sites\example-site'` — тогда флаг можно не писать.

## Первый запуск

1. Откройте браузер-держатель и войдите в Tilda в появившемся окне:

   ```powershell
   node scripts/tilda.mjs --site D:\Sites\example-site session --page 200002
   ```

   Окно разворачивается только на время входа, затем сворачивается. Не закрывайте
   его между командами: сессия Tilda не переживает перезапуск Chrome. Посмотреть в окно
   можно командой `browser show`, свернуть обратно — `browser hide`.

   Не знаете `pageid` нужной страницы? Когда сессия уже есть, перечень страниц проекта
   покажет `node scripts/tilda.mjs --site D:\Sites\example-site page list`.

2. Снимите текущее состояние страницы:

   ```powershell
   node scripts/tilda.mjs --site D:\Sites\example-site snapshot --page 200002
   ```

   Ожидаемый результат: `status: снимки сняты`, файлы в `D:\Sites\example-site\site-baseline\`.

Дальше — [Рабочий цикл](workflow.md): план → `preview` → `apply` → `verify`.

## Если есть доступ к кабинету донора

Донор — аккаунт Tilda с сайтом-образцом. Если владелец добавил аккаунт донора сотрудником
в тестовый проект, сайт переносится через буфер аккаунта, без сборки по разметке.

1. Добавьте в `.env` папки сайта ID проекта донора и отдельный профиль его держателя
   (относительный путь считается от папки сайта):

   ```
   TILDA_DONOR_PROJECT_ID=100002
   TILDA_DONOR_BROWSER_PROFILE=./.browser-profile-donor
   ```

2. Поднимите держатель донора и войдите в аккаунт донора в появившемся окне:

   ```powershell
   node scripts/tilda.mjs --site D:\Sites\example-site browser start --donor
   node scripts/tilda.mjs --site D:\Sites\example-site session --donor
   ```

   Держатель донора работает рядом с тестовым, у каждого свой профиль. Проект донора
   команды только читают.

Дальше — [Рабочий цикл](workflow.md), раздел «Перенос через кабинет донора».

## Проверка на новом сайте

Внутренний API редактора Tilda не является стабильным публичным интерфейсом.
Перед работой на новом сайте выполните минимальную ручную приёмку **на отдельной
копии страницы**:

1. снять снимок (`snapshot`);
2. изменить один текстовый элемент планом (`apply`);
3. убедиться, что `verify` сообщает «расхождений verify: 0»;
4. осмотреть результат в редакторе;
5. выполнить откат по журналу (`rollback`).

До успешной приёмки не применяйте набор к рабочей странице.
Приёмка на втором независимом сайте пока не выполнена.

## Границы инструмента

Набор не предназначен для изменения полей форм, CRM, платежей, доменов и настроек
страницы. Эти действия выполняйте в интерфейсе Tilda вручную. При сборке по референсу
(`reference fetch → catalog capture → reference plan → apply`, см. [Рабочий цикл](workflow.md))
не переносятся Zero Block, HTML-блоки, формы и настройки сайта (шапка и подвал проекта);
их собирают вручную в интерфейсе Tilda.
