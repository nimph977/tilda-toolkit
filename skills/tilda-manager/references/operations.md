# Операции плана и ограничения

Используйте одну операцию на объект `ops`. Адрес блока — `recordid` или `zeroIndex`;
для `set`, `duplicateElement`, `removeElement` и `gallerySet` обязателен селектор
`elem` с одним из полей `elem_id`, `text` или `textIncludes`. Селектор должен найти
ровно один элемент.

| Операция | Назначение |
| --- | --- |
| `set` | Изменяет поля элемента Zero Block. Подходит для текста, геометрии, стилей, `hidden`, ссылок и изображения. |
| `field` | Записывает одно поле обычного блока: `{"field":{"name":"...","value":"..."}}`. |
| `listSet` | Меняет карточки списка через `set`, `add`, `remove` или полную замену `cards`. |
| `blockSet` | Меняет существующие скалярные служебные поля Zero Block, например `ab_height`. |
| `blockHidden` | Скрывает или показывает блок значением `"y"` либо `"n"`. |
| `duplicateElement` / `removeElement` | Создаёт копию элемента или удаляет его из модели. |
| `gallerySet` | Меняет слайды галереи `imgs` через `set`, `add` или `remove`. |
| `moveBlock` / `setOrder` | Меняет порядок блоков. Для `moveBlock` задайте `after`, `before` или `index`; `setOrder` содержит весь порядок `recordid`. |
| `addZero` / `addRecord` | Создаёт блок копированием блока другой страницы. Источник находится внутри операции в `addZero.source` или `addRecord.source`; для `addRecord` нужен `tplid`. |
| `newRecord` | Создаёт стандартный блок из полей без источника: `{"newRecord":{"tplid":"796","fields":[{"name":"title","value":"…"}],"cards":[…],"images":[{"field":"img","file":"…"}]}}`. Имена полей — по каталогу `catalog capture`, поля обеих вкладок («Контент» и «Настройки») идут одним массивом; картинки грузятся с диска до записи. Zero Block (`396`) так не собирается. |

`listSet` имеет вид `{"set":[{"lid":"...","fields":{"li_title":"..."}}]}`;
вместо `lid` допускается `index`. Для добавления используйте
`{"add":[{"after":"end","fields":{...}}]}`, для удаления —
`{"remove":["<lid>"]}`. `gallerySet` использует те же массивы, но новый слайд
обязан содержать `fields.li_img` с URL `https://static.tildacdn.com/...`.

Для `set` адаптивные поля пишутся по `resStrategy`: по умолчанию `scale`; также
доступны `explicit` и `none`. Если явно меняете поле вида `top-res-320`, оно не
пересчитывается. Правка изображения применяется только к элементу типа `image` и
передаётся как `{"image":{"img":"https://...","filewidth":"...","fileheight":"..."}}`.
При обоих размерах инструмент пересчитывает `height` и его адаптивные варианты по
ширине элемента. URL может быть HTTP(S), но проверенный рабочий вариант — CDN Tilda.
`{"image":{"file":"C:/path/image.jpg"}}` поддержан только в `apply`: команда
сначала загружает файл и подставляет `img`, `filewidth`, `fileheight`; такой план не
годится для `preview` или `--dry-run`.

Пример создания блока:

```json
{
  "page": "200002",
  "ops": [
    {
      "id": "new-zero",
      "addZero": {
        "source": { "page": "200001", "recordid": "9000000000001" }
      }
    },
    {
      "id": "new-record",
      "addRecord": {
        "tplid": "215",
        "source": { "page": "200001", "recordid": "9000000000002" }
      }
    }
  ]
}
```

Если все источники на одной странице, `source.page` можно задать один раз в корне
плана, но `source.recordid` остаётся вложенным в каждую операцию. Для подготовки и
сверки должны существовать снимки исходных блоков.

Полная схема `newRecord`:

```json
{
  "id": "b3",
  "newRecord": {
    "tplid": "796",
    "fields": [
      { "name": "title", "value": "Заголовок" },
      { "name": "descr", "value": "Первая строка<br>Вторая строка" },
      { "name": "buttonlink", "value": "https://example.test/" },
      { "name": "margintop", "value": "45px" },
      { "name": "blockbackground", "value": "#ededed" },
      { "name": "title_typo", "value": "{\"color\":\"#ffffff\",\"fontsize\":\"36px\"}" }
    ],
    "cards": [{ "li_title": "Карточка", "li_descr": "Текст", "li_img": "", "li_link": "https://example.test/card" }],
    "images": [
      { "field": "img", "file": "site-reference/demo/images/ab12cd34ef56.jpg" },
      { "card": 0, "field": "li_img", "file": "site-reference/demo/images/cd34ef56ab12.jpg" }
    ]
  },
  "hidden": "n",
  "after": null
}
```

`fields` — поля обеих вкладок шаблона, «Контент» и «Настройки», одним массивом (список даёт
`catalog capture`, поле не из каталога — предупреждение). Оформление блока пишется теми же
полями: отступы `margintop`/`marginbottom` строкой `NNpx`, фон `blockbackground` или `bgcolor`
как `#rrggbb`, типографика — JSON-поле `<семейство>_typo` с ключами `color`, `fontsize`,
`fontweight`, `uppercase`, `lineheight`, `widthpx` (все шесть сервер сохраняет и применяет;
производные `<поле>_color`, `<поле>_fontsize` записать нельзя — `saverecord` их отвергает или
молча игнорирует).

Текстовое поле может содержать `<br>` — сверка считает `<br>`, `<br/>` и `<br />` равными;
другая разметка внутри поля не поддерживается. JSON-поля (`soclinks` формы `[{service, link}]`,
`menuitems` формы `[{title, link, linktarget}]`, `*_typo`) сверяются по канону JSON, поэтому
пересериализация сервера (`\/`, `\uXXXX`, кавычки-сущности) расхождения не даёт.

`cards` собираются в поле `list` вместе с `btitle`
и `bdescr`; `lid` карточкам присваивается автоматически. Карточка может содержать `li_link`,
если шаблон хранит его (`cardKeys` каталога). `images` до записи загружаются
на CDN Tilda из файлов относительно корня репозитория: `field` без `card` — картинка поля
блока, с `card` — картинка карточки. Сверка после записи сравнивает значения полей и
карточки с планом; шаблон, отмеченный в каталоге `available: false`, отклоняется до сети.
Такие операции строит `reference plan`, но их можно писать и вручную. У него два флага,
меняющих состав полей: `--no-styles` не переносит оформление, а `--substitute <от>=<к>`
собирает блоки одного шаблона другим — обход для меню, которое Tilda не даёт добавить.

Поля формы стандартного блока (702, 704 и др.) пишутся полем `forminputs` — JSON-массивом
элементов `{li_type, li_nm, li_name, li_ph, li_req, li_title, li_masktype, li_mask}`
(`li_req: "y"` — обязательное; `li_masktype: ""` + `li_mask` — своя маска); сервер хранит их в
`list`, `lid` и `ls` проставляет инструмент, сверка идёт по `list`. Запись `list` напрямую форме не
помогает: ответ `OK`, но список не меняется. Сообщение об успехе — `formtitlesuccess`,
`formmsgsuccess`. Адрес перехода после отправки `formmsgurl` пишется только операцией с флагом
`"formContent": "reference"` (у `newRecord` и `field`); получатели заявок (`receivers`,
`receivers_names`) и модель формы Zero Block (`inputs`) не пишутся никогда, флаг их не открывает.

HTML-блок (`tplid: "131"`) создаётся операцией `newRecord` с полем `code` рядом с `fields`:
`{"newRecord":{"tplid":"131","fields":[],"code":"<div>…</div>"}}`. Код не больше 25 КБ и без
`<script` — запись скрипта сбрасывает сессию Tilda; `code` у другого шаблона — ошибка до сети.
Сверка сравнивает код перечитанного блока с планом без учёта пробелов по краям.

Инструмент отклоняет значения с `<script` и изменение полей формы, кроме описанного выше.
`listSet` также отклоняется для блока, содержащего поля формы. Перед перестановкой блоков снимите
свежий инвентарь: устаревшие данные могут быть отклонены. После `addZero` или
`addRecord` используйте `moveBlock`, когда положение важно.

Примеры выше описывают формат, но не дают разрешения на запись или публикацию.
